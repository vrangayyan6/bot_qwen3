# 딥 웹 리서치 에이전트 프로젝트 분석

## 1. 프로젝트 개요

이 프로젝트는 **LangGraph**와 **Google의 Gemini API**를 기반으로 구축된, **자동화된 딥 웹 리서치 에이전트**입니다. 사용자가 특정 주제에 대해 질문을 하면, 이 에이전트는 사람처럼 여러 단계에 걸쳐 웹을 탐색하고, 정보를 분석하며, 부족한 부분을 스스로 파악하여 추가 검색을 수행합니다. 최종적으로는 신뢰할 수 있는 출처가 명시된 심층적인 연구 보고서를 생성해주는 것을 목표로 합니다.

핵심은 단순히 한 번의 검색으로 끝나는 것이 아니라, **자율적인 판단**을 통해 정보를 계속 보강해나가는 '리서치 루프(research loop)'에 있습니다.

## 2. 딥 웹 리서치 프로세스 상세 설명 (예시 시나리오)

사용자가 **"최신 AI 기술의 비즈니스 활용 사례"**에 대해 질문한 상황을 가정하여 전체 프로세스를 단계별로 설명합니다.

---

### **1단계: 최적화된 검색어 생성 (`generate_query`)**

-   **시작**: 사용자가 질문을 입력하면, 가장 먼저 `graph.py`의 `generate_query` 노드가 실행됩니다.
-   **역할**: 이 단계의 목표는 사용자의 다소 추상적일 수 있는 질문을 효과적인 웹 검색을 위한 구체적인 검색어 여러 개로 변환하는 것입니다.
-   **과정**:
    1.  `utils.py`의 `get_research_topic` 함수가 사용자의 질문을 명확한 연구 주제로 인식합니다.
    2.  Gemini 모델이 이 주제를 바탕으로 다음과 같이 여러 개의 구체적이고 다양한 관점의 검색어를 생성합니다.
        -   `"2024년 비즈니스 프로세스 자동화에 적용된 AI 사례"`
        -   `"마케팅 분야의 생성형 AI 활용 방안"`
        -   `"금융 분야의 머신러닝 도입 성공 사례"`
-   **결과**: 이렇게 생성된 검색어 목록이 다음 단계로 전달됩니다.

### **2단계: 병렬 웹 리서치 및 정보 수집 (`web_research`)**

-   **시작**: 1단계에서 생성된 각 검색어는 `web_research` 노드로 전달되어 **병렬로 동시에** 검색을 시작합니다.
-   **역할**: 각 검색어에 대해 웹 검색을 수행하고, 신뢰할 수 있는 정보를 수집하며, 모든 정보의 출처를 정확히 기록합니다.
-   **과정**:
    1.  Gemini의 내장된 Google Search 기능을 사용하여 각 검색어에 대한 웹 검색을 수행합니다.
    2.  검색된 웹페이지들의 내용을 수집합니다.
    3.  `utils.py`의 함수들이 수집된 정보들을 처리합니다.
        -   `resolve_urls`: 긴 원본 URL을 짧고 관리하기 쉬운 형태로 변환합니다.
        -   `get_citations` 및 `insert_citation_markers`: 텍스트의 특정 부분이 어떤 웹페이지에서 왔는지 출처를 자동으로 찾아, 본문에 인용 표시를 삽입합니다. (예: "...50% 단축시켰습니다 `[source-0-1]`.")
-   **결과**: 인용 정보가 포함된 여러 개의 텍스트 뭉치와 출처 URL 목록이 생성됩니다.

### **3단계: 정보 분석 및 '지식의 공백' 탐지 (`reflection`)**

-   **시작**: 2단계에서 수집된 모든 정보가 `reflection` 노드로 모입니다.
-   **역할**: 지금까지 수집된 정보가 충분한지, 혹은 편향되거나 빠진 내용은 없는지 **스스로 비평하고 판단**하는 핵심 단계입니다.
-   **과정**:
    1.  수집된 모든 텍스트를 종합하여 중간 요약본을 만듭니다.
    2.  Gemini 모델이 이 요약본을 분석하여 "지식의 공백(knowledge gap)"을 찾습니다. (예: "AI의 긍정적인 활용 사례는 많지만, 도입 시 발생하는 윤리적 문제나 데이터 보안에 대한 내용이 부족하다.")
    3.  이 지식의 공백을 메우기 위해 **추가 검색어(follow-up queries)**를 생성합니다.
-   **결과**: 정보의 충분성 여부, 발견된 지식의 공백, 그리고 새로운 추가 검색어 목록이 생성됩니다.

### **4단계: 리서치 루프 (`evaluate_research`)**

-   **시작**: 3단계의 분석 결과가 `evaluate_research` 로직으로 전달됩니다.
-   **역할**: 리서치를 계속할지, 아니면 마무리할지를 결정하는 분기점입니다.
-   **과정**:
    -   **계속 진행**: 정보가 아직 불충분하다고 판단되면, 새로 생성된 추가 검색어들을 가지고 **2단계(웹 리서치)로 다시 돌아가** 전체 과정을 반복합니다.
    -   **마무리**: 정보가 충분하다고 판단되거나 최대 반복 횟수에 도달하면, 다음 단계로 이동합니다.

### **5단계: 최종 보고서 생성 (`finalize_answer`)**

-   **시작**: 모든 리서치 루프가 끝나고 정보가 충분히 모였을 때 `finalize_answer` 노드가 실행됩니다.
-   **역할**: 지금까지 수집되고 정제된 모든 정보를 종합하여, 사람이 읽기 좋은 형태의 최종 보고서를 작성합니다.
-   **과정**:
    1.  Gemini 모델이 전체 정보를 바탕으로 서론, 본론, 결론의 구조를 갖춘 일관된 글을 작성합니다.
    2.  본문에 삽입되었던 짧은 출처 표시들을 다시 원래의 전체 URL 주소로 변환합니다.
    3.  보고서의 마지막에는 참고한 모든 웹사이트의 목록을 "참고문헌" 형태로 깔끔하게 정리하여 첨부합니다.
-   **결과**: 사용자는 주제에 대한 심층적인 분석과 신뢰할 수 있는 출처 목록이 포함된 최종 결과물을 받게 됩니다.

## 3. 핵심 코드 파일의 역할: `graph.py`와 `utils.py`

이 리서치 에이전트의 동작은 `graph.py`에 정의된 **프로세스 설계도**와 `utils.py`에 담긴 **핵심 기술 도구**들의 조합으로 이루어집니다.

### **`graph.py` : 리서치 전략가**

`graph.py`는 전체 리서치 과정의 **흐름을 제어하는 총감독**과 같습니다. LangGraph를 사용하여 각 단계를 '노드(node)'로 정의하고, 이 노드들을 어떻게 연결할지 결정합니다.

-   **`generate_query` (노드):** 리서치의 첫 단추.
-   **`web_research` (노드):** 실질적인 정보 수집 행동대원.
-   **`reflection` (노드):** 중간 분석 및 전략 수정.
-   **`finalize_answer` (노드):** 최종 보고서 작성.
-   **`evaluate_research` (조건부 엣지):** 리서치 지속/종료를 결정하는 분기점.

### **`utils.py` : 다재다능한 기술 전문가**

`utils.py`는 각 단계에서 필요한 **구체적이고 실질적인 작업들을 처리하는 도구 모음**입니다.

-   **`get_research_topic(messages)`:** 대화에서 핵심 연구 주제 추출.
-   **`resolve_urls(...)`:** 긴 URL을 관리하기 쉬운 짧은 ID로 매핑.
-   **`get_citations(...)`:** 텍스트와 출처(URL)의 근거 데이터 추출.
-   **`insert_citation_markers(...)`:** 텍스트 본문에 출처 인용 마커 자동 삽입.

결론적으로, **`graph.py`가 리서치의 '뇌'로서 전체 과정을 지휘**한다면, **`utils.py`는 '손발'처럼 움직이며 데이터를 정제하고, 출처를 기록하고, 정보를 가공하는 등 세부적인 기술 구현을 담당**합니다.

## 4. 최종 요약

이 프로젝트는 **단순한 정보 검색 도구가 아니라, 스스로 생각하고 학습하는 '자율 리서치 에이전트'**입니다. 체계적인 프로세스를 통해 질문을 깊이 이해하고, 정보를 수집 및 비판적으로 검토하며, 필요한 정보를 얻기 위해 자율적으로 검색을 반복합니다. 이를 통해 사용자는 단편적인 정보가 아닌, 여러 관점이 종합되고 출처까지 명확하게 정리된 **하나의 완성도 높은 심층 분석 보고서**를 얻게 됩니다.
